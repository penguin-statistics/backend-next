# AGENTS.md

Guidance for coding agents (and people) changing this repository. Keep it short and true: if you change a command,
a path or a rule below, update this file in the same PR.

backend-next is the Penguin Statistics v3 backend in Go (module `exusiai.dev/backend-next`): the public API under
`/PenguinStats/api/v2` (admin and health routes under `/api`), the drop report pipeline (NATS JetStream → report
worker → PostgreSQL), the workers that calculate the drop matrices, the server-rendered stats pages
(`/{zh,en,ja,ko}/result/...`) and their sitemaps, and the tooling of the cold storage of old reports. Built with
fiber v2, uber-go/fx and bun.

Only want to use the data? You do not need this repo: see https://developer.penguin-stats.io/public-api; the data
is CC BY-NC 4.0.

## Setup

- Go: the `go-version` in `.github/workflows/test.yml`, which the Dockerfile's builder image also uses. `go.mod`
  keeps `godebug default=go1.19` so that raising its `go` directive changes no runtime default of the binary; keep
  that line.
- cgo is required: `duckdb-go` links DuckDB's prebuilt static library, built for glibc (no Alpine/musl). Its DuckDB
  release is repeated as `DUCKDB_VERSION` in the Dockerfile and in `test.yml`: bump `duckdb-go` and both of them
  together.
- Services: PostgreSQL (CI uses 14), Redis, NATS with JetStream (`nats-server -js`).
- Config: environment variables `PENGUIN_V3_*` (`internal/app/appconfig/spec.go`, envconfig with `split_words`, so
  `PostgresDSN` is `PENGUIN_V3_POSTGRES_DSN`). A gitignored `.env` at the repo root is loaded when present. Never
  commit `.env` or production values.
- Run: `go run . start`. Without `start` (`go run .`, and so `make dev`) it only prints the help;
  `go run . run-script` lists the maintenance commands (archiving, cold storage).

## Checks

Run what CI (`.github/workflows/test.yml`) runs before you push:

```sh
go vet ./...
go vet -tags workerbench ./internal/workers/calcwkr/ ./internal/service/
go vet -tags compressbench ./internal/server/httpserver/
scripts/coldstore/backfill_test.sh
go test -race -count=1 $(go list ./... | grep -v '/backend-next/test$')
```

- Tests that need PostgreSQL, Redis, NATS or DuckDB's postgres extension skip unless `PENGUIN_TEST_POSTGRES_DSN`,
  `PENGUIN_TEST_REDIS_URL`, `PENGUIN_TEST_NATS_URL` and `PENGUIN_TEST_DUCKDB_EXTENSION_DIR` are set; `test.yml`
  shows how CI provides each. Point them only at disposable services.
- `test/` holds end-to-end tests of the whole app against a fully configured environment; CI leaves it out.
- Benchmarks sit behind build tags (`workerbench`, `consumerbench`, `compressbench`); the README describes the
  report consumer benchmark.
- gofmt the files you change only: `gofmt -l .` is not empty on `main` (mostly the swag comment blocks of
  `internal/controller/v2`).

## Rules

- **Report path**: do not loosen anything that guards `POST /PenguinStats/api/v2/report*`: request validation,
  `reportverifs` and the reject rules, the idempotency middleware (`X-Penguin-Idempotency-Key`, so a retried
  submission counts once), the recognition payload decryption. Fake reports corrupt everyone's statistics. Changes
  there need a maintainer's review.
- **The v2 API is public**: third-party tools parse it. Add fields; do not rename, remove or retype them.
  GET endpoints with a `server` query parameter (`CN`, `US`, `JP`, `KR`) fall back to `CN` without it; the report,
  recognition and advanced query request bodies require it.
- **Data semantics**: drop rate = `quantity / times` (per run, can exceed 1); `start` and `end` are epoch
  milliseconds, `[start, end)`, calculated at second precision; `end: null` in the API means the window is still
  open (the database stores a far-future sentinel); the global matrix leaves out `quantity = 0`. How time ranges and
  `accumulable` drop infos split a matrix (`internal/service/time_range.go`, `drop_matrix.go`) is a maintainer
  decision: do not change it in passing.
- **Stats pages** read only `service.SEOData`, which never waits for the database. Keep database queries and the
  advanced query out of their request path.
- **Swagger**: after changing handler annotations, regenerate with the swag version in `go.mod`
  (`go run github.com/swaggo/swag/cmd/swag@v1.16.2 init --parseDependency --parseInternal --parseDepth 2`) and
  commit `docs/`. A full regeneration on `main` also changes a few unrelated lines: keep those out of your PR.
- **Feature flags** (`PENGUIN_V3_*_ENABLED`) default to off; production sets them in the manifests repository
  (`applications/backend`).
- **MCP Registry listing**: `server.json`, once added, carries a version of its own (not the backend's release tag)
  and only the public MCP URL, never a preview host.
- **License**: code MIT (`LICENSE`); data CC BY-NC 4.0, which the stats pages link with `rel="license"`.
- No secrets, tokens, internal host names or IP addresses in code, tests, comments, commit messages or PRs.

## Pull requests

- Branch from `main`, open the PR against `main`; PRs are squash-merged.
- Conventional commit titles with a scope: `feat(report): ...`, `fix(reportverifs): ...`, `perf(service): ...`,
  `chore(deps): ...`. A stack of PRs prefixes `[topic n/m] `. The body says what changes and why, the risk, and how
  to verify it after a release.
- If you change public API behaviour or data semantics, say so in the PR.
- Releases are maintainers' work: a `vX.Y.Z` tag on `main` builds the image (`build-release.yml`), and ManifestBot
  writes it into the manifests repository (`applications/backend/values-prod.yaml`), which Argo CD deploys.
